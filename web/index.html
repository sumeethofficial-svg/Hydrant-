Hydrant keeps every MCP tool definition in a HydraDB graph and hands the agent only what the task needs: the tools, the lookups those tools depend on, and the entities it has already resolved. Every finished task rewrites a little of the graph, so the next answer is sharper.

What lives in the graph

  
Black edges come from the tool definitions at ingest. Brass edges and weights are written by the learning loop. 

  
(Server)-[:PROVIDES]->(Tool)
(Term)-[:MENTIONS {w}]->(Tool)            a word points at a tool; weights move with every outcome
(Term)-[:NAMES]->(Server)                   "slack", "github" and learned ones: "pod" names kubernetes
(Tool)-[:NEEDS]->(Resource)                 slack_post_message needs a channel id
(Resource)-[:YIELDED_BY {w}]->(Tool)      slack_list_channels can look one up
(Term)-[:MEANS]->(Term)                     learned alias: "pr" means "pull_request"
(Tool)-[:THEN]->(Tool)                      learned workflow: search_issues, then add_issue_comment
(Term)-[:DENOTES]->(Entity)                 learned: "releases" is channel C04REL9K2
(Resource)-[:HOLDS]->(Entity)





Built on HydraDB, the open-source graph engine. Tool definitions are real, harvested from 27 public MCP servers.
